## Fixes found by the gate

1. **MinIO images can no longer be pulled (5f4c438).** `quay.io/minio/*` answers `unauthorized` and
   `docker.io/minio/*` "repository does not exist": MinIO stopped publishing images. In minio mode the MinIO
   pod and the bucket Job sat in `ImagePullBackOff` forever, so no cluster ever left `Provisioning`. The
   defaults are now the community builds of the same sources, `docker.io/pgsty/minio` and `docker.io/pgsty/mc`,
   pinned to release tags; `MINIO_IMAGE` and `MC_IMAGE` still override them (the operator.yaml comment says so).
   Choosing that image source is a judgement call the user should confirm (a mirror of their own works too).

2. **Deleting a `PharosCluster` deleted every index in minio mode (4bec479, final review I1).** Every
   dependent carried an owner reference, so the MinIO PVC and its credentials Secret were garbage-collected
   with the cluster. Both are now created without one and are adopted by a cluster applied again under the same
   name. The `reapply` phase checks this for real (run `e2e-full3` below).
3. **No pod could download an embedding model (98a193c).** uid 10001 has no home directory, and pharos caches
   models under `${user.home}/.djl.ai`, so with `spec.embeddings` set nothing could be downloaded. The
   entrypoint now passes `-Duser.home=$PHAROS_HOME`, which puts the model cache on the PVC. Found by the
   embeddings run.

The final review's I2 (b208d9d: catalog ids this build cannot parse are refused by `--check` and never make
readers drop shards) has unit tests only; the e2e has no Phase 6 catalog to downgrade from.

The driver's own problems found while writing it (wrong mount path, the bucket's key prefix, `managedFields`
hidden by default, a replica timeline that could miss a change applied within one poll) are fixed in the
script and are not product bugs.

## Deviations

- **Embeddings in a separate run.** The main run uses `embeddings: none`, so its 2 writers and up to 3 readers
  fit in 7g. Vectors are covered by the embeddings run below (1 writer, 1 reader, 9g), which the user approved.
  The pods download the model themselves, and nothing is copied in.
- **Takeover by the same identity.** The force-deleted pod comes back under the same name (a StatefulSet) and
  is a writer like any other: after the lease TTL either writer may take it. In this run the re-created
  `e2e-writers-1` took `alpha` back (in an earlier run, `e2e-writers-0` did the same with its own). A lease
  moving to *another* writer is covered by step 7b, where `alpha` moved from `e2e-writers-1` to
  `e2e-writers-0` while a commit was pending.
- **Upgrade with one reader.** The upgrade runs after scale-down, so readers are at `min: 1` and the reader
  roll is a short outage. Queries during the upgrade are not part of the pass criteria (steps 5–7) and are not
  counted.

## How to run

```bash
# on a host with minikube, kubectl, docker and python3 (here: the build server)
bash scripts/operator-e2e.sh --start            # creates profile pharos-e2e with calico if needed
E2E_PHASES=fixture,cluster,ready bash scripts/operator-e2e.sh --keep   # a subset, keep it installed
bash scripts/operator-e2e.sh --delete-profile   # delete the minikube profile afterwards
bash scripts/operator-e2e.sh --start --with-embeddings   # the vector run (9g profile; pods download jina-v2-code)
```

Output (operator logs before and after the restart, the replica timeline) goes to `E2E_OUT`
(default `./e2e-out`).
